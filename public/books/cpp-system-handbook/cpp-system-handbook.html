内存主线：一句 C++ 代码的内存之旅

从"内存住哪"一路走到"怎么管好内存"，并在缺页处接上 OS 缓存层级、在代码执行处接上 CPU 流水线。

1
内存分区模型

进程跑在独占虚拟地址空间，按段划分 .text/.rodata/.data/.bss、堆、mmap、栈与内核空间，先建立"代码和数据各住哪"的地图；机器码在磁盘，运行时由加载器按需分页映射进 .text。

↓
2
new 与 malloc

要动态内存就用 malloc（C 库函数）或 new（C++ 运算符，先 operator new 分配、再调构造）。new 默认底层走 malloc；malloc 按大小分流：小对象 brk 推堆顶、大对象 mmap 匿名映射。

↓
3
页与 chunk

打通两个粒度——malloc 切的是 chunk（库的逻辑单位，可小于一页、也可跨多页），OS 分配的是页（4KB，物理内存最小单位）。sbrk 一次"批发"按页对齐的一大段，再切成 chunk"零售"。

↓
4
缺页分配（关联 OS）

malloc 只预留虚拟地址，真正访问且页未映射时触发缺页：内核分配物理页框、建 PTE、回填 TLB，再重试指令。五种缺页：首次访问、COW、栈增长、swap 换入、文件页回收。

↓
5
RAII 与智能指针（防泄漏）

解决"怎么管"——RAII 把资源绑栈对象，unique/shared/weak 按所有权自动析构；配合 make_*、基类 virtual 析构、标准容器，几乎不手写 delete。

支线一 · 缺页分配 → 串起 OS 缓存层级

一次访存先经 MMU 查 TLB、再查多级页表得到物理地址，内容按 L1/L2/L3→RAM 逐级取，缺页由内核补、必要时从磁盘读。这把"内存分配"和"页表/TLB/缓存"串成一条完整时序。

支线二 · C++ 代码执行 → 串起 CPU 流水线

.text 里的指令被 CPU 取指执行，五级流水线 IF/ID/EX/MEM/WB 重叠，数据/控制/结构冒险靠转发、停顿、分支预测解决，再用乱序与多发射提速。这把"内存里的指令"和"CPU 怎么跑"串起来。

并发主线：线程如何被切换、又如何安全共享

从"进程和线程的区别"走到"共享数据三大问题"，把创建进程/线程、上下文切换、调度与内存序串成一条线。

1
进程 vs 线程

进程是资源分配单位、各有独立地址空间；线程是 CPU 调度单位，共享进程的代码/堆/文件，独占栈、寄存器、PC。

↓
2
创建进程 / 线程时发生什么

创建进程：fork() 让内核新建 task_struct、PID、内核栈，并以 COW 复制 mm 与页表；execve() 再建全新 VMA、加载 ELF、把 argv/envp 放栈顶、设入口 PC，物理页延迟到首次缺页才真正分配。

创建线程：std::thread 只是句柄；pthread 用 mmap 分配线程栈、建用户态 TCB；内核 clone（带 CLONE_VM）建 task_struct 与内核栈、共享同一套页表，然后入运行队列。

3
上下文切换哪些内容

六步骤——触发 → 存现场（PC/寄存器/栈指针入 TCB）→ 选线程 → 地址空间判断（同进程 CR3 不变、跨进程换 CR3 且 TLB 失效，PCID 可缓解）→ 装现场 → 跳转。

4
CPU 调度方式切换

线程在就绪/运行/阻塞三态间转换，CFS 选 vruntime 最小者；触发时机含时间片用完、阻塞、抢占、终止。并发是单核时间片轮转，并行是多核同时执行。

↓
5
共享数据访问三问题

同一份共享数据在多核下要同时回答原子性、有序性、可见性，下面分三条展开。

a · 原子性（操作不可分割）

mutex 先 CAS 抢 state，失败经 futex 睡眠、解锁时 wake 唤醒；atomic 靠 LOCK/CAS 与 MESI 硬件缓存锁，只锁相关缓存行；多核高频写要防伪共享，用 alignas(64) 对齐。

b · 有序性（禁止非法重排）

用内存序 release/acquire（更强用 seq_cst），配合内存屏障，让编译器与 CPU 不把关键读写越过屏障重排。

c · 可见性（写及时被看到）

MESI 保证最终一致：写要先拿独占、向其他核发失效；但写可能停在 store buffer，需内存屏障冲刷。release/acquire 配对建立 happens-before——解锁=release、加锁=acquire，写方 release 前的所有写，读方 acquire 后保证可见。注意 C++ 的 volatile 不保证多线程可见性。

PART 01

C++ 内存管理

虚拟地址空间如何分区，内存如何被分配、翻译与回收，以及现代 C++ 如何靠 RAII 管理资源。

1.1进程虚拟地址空间与内存分区

进程运行在独占的虚拟地址空间中，这段空间按用途划分成不同的段。机器码在编译链接后先存于磁盘可执行文件，运行时由加载器按需分页映射进内存，而不是编译后直接整体装入。

1.2三个高频误区

误区一：const 都在常量区函数内的 const 局部变量仍在栈上，const 只是编译器层的只读约束；只有全局 const、constexpr、字符串字面量才进 .rodata。
误区二：虚指针 vptr 在常量区vptr 位于对象自身内存（堆或栈），随对象走；只有它指向的虚函数表 vtable 才在只读段。
误区三：malloc 会构造对象malloc 只分配原始内存，不调用构造函数；C++ 中在原始内存上构造对象是 placement new 的职责。

1.3malloc/free 与 new/delete 的关系

malloc/free 是 C 库函数；new/delete 是 C++ 运算符（可重载）。new 表达式做两件事：先调 operator new 分配原始内存（默认实现底层通常就是 malloc），再在其上调用构造函数；delete 则先调析构、再 operator delete（通常底层 free）。

为什么要"包装"一层面向对象的需要：分配的同时构造、释放时析构，并获得类型安全。malloc 只给一块原始内存，对对象一无所知。
对比项malloc / freenew / delete
性质C 库函数C++ 运算符，可重载
返回值void*，需强转类型化指针
失败行为返回 NULL抛 bad_alloc（nothrow 版返回 nullptr）
大小手动指定字节数自动计算 sizeof(T)
构造/析构不调用自动调用
数组无概念new[] / delete[]

1.4malloc 内部机制：glibc ptmalloc

ptmalloc 按请求大小分流。小对象走堆区、用分级空闲链表管理；大对象直接 mmap。

小对象（< 阈值）默认阈值 128KB，运行中动态调整，64 位上限约 32MB。通过 brk/sbrk 推高 program break，内部用 bins 管理空闲块。
大对象（≥ 阈值）直接 mmap 匿名映射（MAP_ANONYMOUS | MAP_PRIVATE），free 时 munmap 立即归还 OS。

小对象的空闲块查找顺序

tcache线程缓存
→
fastbins快速
→
small bins小块
→
unsorted未排序
→
large bins大块
  • fast/small 按尺寸精确匹配，只有 large bin 才是 best-fit；
  • 分配时先查 bins 有无合适块，没有才推堆顶向 OS 申请；
  • free 后 chunk 进 bins 缓存、不立即归还 OS，相邻空闲块合并以防碎片；
  • sbrk 是"推 brk"的系统调用封装，brk 即程序堆顶边界（program break）。
32 位地址空间的兜底当 brk 推不动（碰到 mmap 的 VMA）时，ptmalloc 在 sysmalloc 中 fallback 到 mmap 独立块；只有地址空间彻底耗尽才返回 NULL / bad_alloc。

chunk 与页的关系

  • sbrk 一次"批发"一大段（按页对齐，如 128KB），ptmalloc 再把它切成一个个 chunk"零售"；一个 chunk 可小于一页（多个 chunk 挤在同一页里），大 chunk 也可跨多页；
  • 可用 /proc/self/maps 查看进程的 VMA：brk 堆与 mmap 区是各自独立的条目，权限、起止地址一目了然。
物理内存不够：overcommit 与 OOM Killer Linux 默认允许内存超发（overcommit），所以 malloc 往往成功，等真正写那些页时才可能出问题。物理内存紧张时内核依次处理：① 回收可丢弃的页缓存 / buffer；② 把匿名页（堆/栈）换出到 swap；③ 仍不足则触发 OOM Killer 按策略挑选进程杀掉。超发策略可用 /proc/sys/vm/overcommit_memory 调整。64 位下不缺虚拟地址，真正会卡住你的是物理内存。

1.5页、页表、MMU、TLB 与缺页

页是 OS 管理内存的最小单位，x86 默认 4KB（212），物理侧对应等大的页框。虚拟地址 = 虚拟页号 VPN（高位）+ 页内偏移（低 12 位）= VPN×4096 + 偏移。

  • 页表：内核拥有的映射数据结构，物理放在 RAM，用户态不可直接读写；
  • MMU：硬件，每次访存自动查页表翻译；TLB 位于 MMU 内、CPU 芯片的 SRAM 上，缓存最近的翻译结果；
  • 物理地址 = PFN<<12 | 偏移，页内偏移在虚拟/物理中是同一个值。例：PFN=5、offset=100 → 20580；VPN8、off0 → 32768 = 0x8000；
  • 多级页表按需分配：没用到的地址区间不建下级表，用很少内存支撑巨大地址空间；查得慢的问题靠 TLB 缓解。

多级页表的具体层级

  • x86_64（48 位）：4 级——PML4 → PDPT → PD → PT，每级 512 项、对应 9 位地址；
  • 32 位 x86：2 级——PD（PDI，10 位）→ PT（PTI，10 位），每级 1024 项；
  • 单级页表须一次性建全 2²⁰ 项（约 4MB/进程），二级页表只用 3 页时总共仅约 8KB（1 个页目录 + 1 个页表）——这就是"按需分配、稀疏省内存"，20 位是寻址能力、不是必须建满的表。

缺页时内核具体做什么（回答"回填 TLB、L1？"） ① 分配一个空闲物理页框；若内容在磁盘（swap/文件页），先把数据读进该页框；② 建立/更新 PTE，把虚拟页映射到该页框并设好权限；③ 回填 TLB，再返回用户态重试那条触发缺页的指令。 TLB 会被回填，但 L1 不是内核主动写的。L1 缓存的是指令/数据内容，等指令恢复执行、真正访问该地址时，硬件才按缓存行从 L2/L3/RAM 加载（demand fill），并顺带利用空间局部性预取相邻行。

内核如何管理物理内存：buddy / slab / page cache

伙伴系统 buddy最底层按页 / 页块（1,2,4,8…页）分配，相邻空闲块可合并，防止外部碎片。
slab / slub内核自己的小对象池，按类型缓存 task_struct、inode、file、sk_buff，免重复初始化（Linux 默认 slub）。
page cacheRAM 里缓存的磁盘文件内容；干净页内存紧张时可直接丢弃，脏页先刷盘。

1.6RAII 与智能指针

RAII 把资源生命周期绑定到栈对象：构造时获取资源、析构时释放。栈对象离开作用域必然析构（异常栈展开也会析构），且不限于内存——lock_guard 管锁、fstream 管文件。

unique_ptr独占所有权，同一时刻只有一个持有者。注意：它是"独占所有权"，不是单例。
shared_ptr共享所有权，引用计数是原子操作；但不自动给所指对象加锁，多线程改同一对象仍需 mutex。
weak_ptr不增 use_count，用于打破循环引用。
  • 强/弱计数始终在同一控制块：use_count 归零销毁对象，weak_count 归零才释放控制块；
  • make_shared 把对象与控制块合并为一次分配（少一次分配、缓存友好；但长命 weak_ptr 时整块延迟释放）；shared_ptr(new T) 是两次分配。
那单例到底该怎么实现单例靠私有构造 + static 接口，与 operator new 无关（重载 operator new 只改内存来源、不限制实例个数）。C++11 起函数内 static 局部变量的初始化是线程安全的： 
class Singleton {
public:
    static Singleton& get() {
        static Singleton instance; // C++11 起初始化线程安全
        return instance;
    }
private:
    Singleton() = default;
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
};
现代实践：如何防止内存泄漏 ① 优先栈对象 / 值语义，优先用标准容器（vector 等）管理动态对象；② 必须堆分配时用 make_unique / make_shared；③ 裸指针或引用仅用于非拥有的观察，不负责删；④ 基类析构函数加 virtual；⑤ 一切资源用 RAII 类型（lock_guard、fstream、智能指针）；几乎不手写 delete。

2.1存储层级与 CPU 缓存

CPU 内有两类 SRAM，职责不同：一类缓存指令/数据内容，一类缓存地址翻译。

  • L1 分 L1i（指令）与 L1d（数据）；L2 核私有；L3 多核共享；
  • TLB 缓存地址翻译，分 iTLB（IF 取指用）与 dTLB（MEM 数据用）；
  • 缓存基于两种局部性：时间局部性（刚用过还会用）与空间局部性（用到相邻数据）；
  • 缓存与缓存一致性的最小单位是缓存行，64B。
指令地址 vs 数据地址指令地址是 PC 指向的 .text 里的位置；数据地址是 load/store 操作的堆/栈位置。取指走 iTLB + L1i，读写数据走 dTLB + L1d。
什么情况下数据在 L2/L3 而不在 L1数据首次进入一般先到 L1，并不是"主动越过 L1 存放"。但 L1 最小（约 32KB），装满后新行会把旧行挤出（evict）。 多数 CPU 采用包含（inclusive）策略，L1 是 L2 的子集：被 L1 淘汰的行通常仍保留在 L2/L3，所以 L1 miss 时先查 L2、再 L3，命中就逐级取回、不必访问 RAM；多核共享的数据主要放在共享的 L3。 一次性遍历大数组这类没有时间局部性的流式访问，可用非临时（non-temporal）指令旁路 L1，避免把有用数据冲掉。不同架构也有 exclusive（不包含）策略。

2.2MESI 缓存一致性

多核各有私有缓存，靠 MESI 协议通过总线 snooping（监听）与失效消息保证缓存最终一致。

状态含义能否直接写
M本核独有、已修改、与内存不一致可以
E本核独有、干净可以（转 M）
S多核可同时持有、干净否，先失效别人
I无效，无可用数据否，先获取
关键：一致 ≠ 即时可见MESI 保证最终一致，但不保证可见时机；加上编译器/CPU 重排，多线程仍需内存屏障或锁来保证正确性。
为什么 MESI 是硬件层面，而不是物理分区MESI 由 CPU 的缓存控制器 + 总线监听逻辑在硅片电路里实现，状态流转完全由硬件自动完成，OS 和应用无感知、也不参与；它在纳秒级响应，若靠 OS 软件中断处理根本来不及。 它不是把缓存物理切成四块区域：缓存还是同一块 SRAM，只是每个缓存行的 tag 里额外用 2 个状态位编码 M/E/S/I。硬件在总线上自动广播/监听请求与失效消息。这也正是 LOCK 指令能直接利用 MESI 做缓存锁的原因。

→

→

三类指令的数据路径

类型路径是否碰内存
loadRAM → MEM → 寄存器是

打通的关键认知"EX 都要算术了，为什么 MEM 才读数据"——误区根源是以为一条指令瞬时一次做完。实际上读内存要靠独立的 load 指令先把数据搬进寄存器，ALU 只对寄存器操作；指令是分阶段、可与其他指令重叠的。

流水线冒险（hazard）与处理

冒险成因处理手段
数据冒险后一条指令要用前一条还没算完的结果转发（旁路 forwarding），必要时停顿 stall

流水线的收益（时空图量化）4 条指令若不流水线要 20 个周期（4×5），五级流水线重叠后约 8 个周期即可全部完成；单条指令延迟不变，但单位时间完成的指令数（吞吐）大幅提升。

2.4现代 CPU 的三大提速手段

流水线多条指令处在不同阶段、重叠执行，提升吞吐。
乱序执行 OoO操作数就绪的指令先执行，不必死等；经 ROB（重排序缓冲）最终按序提交，保证结果正确。
多发射超标量，一个周期同时启动多条指令（4–6 宽），配合 SIMD；分静态（编译器排）与动态（硬件调度）。
落盘与写回的区别WB 写回的是寄存器；匿名页（堆/栈，无文件 backing）默认只在 RAM、不落盘。只有软件显式 write 才涉及磁盘：先落 page cache（脏页）立即返回，由 flusher 线程稍后（约 30s 或内存紧张时）异步刷盘，fsync 强制等待刷完，与流水线 WB 无关。
PART 03

并发与多线程

多个执行流如何共享与隔离，上下文如何切换，以及如何用原子、内存序和锁保证正确。

3.1进程 vs 线程：共享什么、独占什么

线程共享（进程级）代码段、堆、全局/静态数据、页表（地址空间）、文件描述符。
线程独占（线程级）线程栈、寄存器状态（含 PC）、栈指针、TLS、信号掩码、线程 ID。

进程是资源分配的最小单位（独立地址空间），线程是 CPU 调度的最小单位，一个进程至少含一个线程。

3.3CPU 如何调度线程

并发（单核）多线程按时间片快速轮转，微观交替、宏观同时。
并行（多核）多个线程在同一时刻真正同时执行，每个核心有自己的运行队列。

线程在就绪、运行、阻塞三态间转换；调度触发时机：时间片用完（时钟中断）、主动阻塞（等 I/O/锁/sleep）、高优先级线程唤醒抢占、线程终止。Linux CFS 调度器选择 vruntime（虚拟运行时间）最小的线程上 CPU。

教学简化说明上述调度策略（CFS、三态、触发时机）与 3.2 的切换步骤均为教学简化模型；真实 Linux 还含调度类（deadline/rt/cfs）、nice 优先级、负载均衡、cgroup、唤醒抢占等大量机制，具体行为随内核版本而异。

3.4竞态条件与临界区

一句 count++ 在机器层面是 load → add → store 三条指令，线程可能在任意两条之间被切换。两个线程各加一次，正确结果应为 2，时序交错后可能都基于旧值 0、最终只得到 1（丢更新）。

  • 竞态条件：结果取决于线程执行的精确先后，因而不可预测；
  • 临界区：访问共享资源、中途不能被插入的代码；处理它的代码分四区段——进入区、临界区、退出区、剩余区；
  • 解决办法是让临界区互斥：同一时刻只放一个线程进入。

四个区段各自是干嘛的

区段职责典型代码
进入区 entry申请进入、检查/设置标志，决定本线程能否进入mutex.lock()
临界区 critical真正访问共享资源、必须互斥的那段代码count++
退出区 exit释放访问权、清标志，让其他线程能进入mutex.unlock()
剩余区 remainder其余不碰共享资源的代码普通计算、I/O 等

3.5原子操作与 std::atomic

原子性指一个操作要么完整执行完、要么不执行，中间状态对其他线程不可见。std::atomic<T> 编译后使用硬件原子指令：x86 的 LOCK 前缀（如 LOCK XADD）、CMPXCHG；现代实现靠 MESI 做缓存锁，只锁定涉及的缓存行而非整个总线。

数据竞争是未定义行为普通非原子变量被多线程并发写，属于 undefined behavior，不是"结果随机"那么简单。单变量计数/标志位用 atomic，多变量或一段逻辑用 mutex。

3.6内存模型与内存序

并发有三个独立问题：原子性（操作不可分）、可见性（写何时对别人可见）、有序性（编译器/CPU 重排）。内存序是 C++ 标准定义的抽象（非 OS 概念），由编译器翻译为硬件屏障（如 MFENCE）。

内存序语义
relaxed只保证原子性，无跨线程顺序，适合纯计数
acquire读操作，后续读写不重排到它前面
release写操作，之前读写不重排到它后面
acq_rel读改写兼具两者
seq_cst最强、默认，再加全局唯一总顺序
release/acquire 配对生产者先写数据再 release 置标志，消费者 acquire 读到标志后，生产者 release 之前的所有写都对其可见，构成 happens-before。consume 已不推荐使用。

3.7锁、futex 与无锁

std::mutex（底层 futex）先在用户态 CAS 抢锁，无竞争直接成功；失败才 futex_wait 陷入内核睡眠，解锁时 futex_wake 唤醒。
自旋锁抢不到就循环 CAS 忙等，不睡眠、无切换开销，适合持锁极短；单核上纯烧 CPU。
无锁 CAS读旧值→算新值→CAS 替换，失败重试；无阻塞、免疫死锁。经典坑 ABA，用版本号解决。
对照 Java：ReentrantLock/AQS 与 synchronized 锁升级 ReentrantLock（AQS）：CAS 抢 state（0 空闲→1 占用），抢不到就封装成 Node 入队、LockSupport.park() 挂起，释放时改 state 并 unpark 队首——与 futex 的"用户态 CAS 快路径 + 失败睡眠"同构。 synchronized：在对象头 Mark Word 里做锁升级——偏向锁（单线程，CAS 记录线程 ID，几乎零开销）→ 轻量级锁（多线程但竞争不激烈，CAS 自旋，对应自旋锁）→ 重量级锁（竞争激烈，膨胀成 monitor，没抢到的挂起，对应 futex 睡眠）。 对应关系：CAS 抢 state = AQS；自旋 = 轻量级锁；futex 睡眠 = 重量级锁。
死锁四条件（同时满足才发生）互斥、持有并等待、不可抢占、循环等待。破解：固定全局加锁顺序、try_lock 回退、超时、减小锁粒度。

3.8伪共享、缓存行对齐与 thread_local

伪共享 false sharing缓存一致性以缓存行（64B）为单位。若两个线程各自的变量恰好挤在同一行，一方写会让另一方整行失效，缓存行在核间反复弹跳、性能骤降——逻辑上不共享，物理上却被拖累。
  • 用 alignas(64) 让高频写的变量各自独占缓存行，或手动 padding；代价是少量空间换大幅性能；
  • thread_local 让变量每线程一份独立副本，线程开始创建、结束销毁，从根上不共享、无需加锁；适合私有缓冲区、分配器、随机数种子等。
一条工程决策线能用栈/thread_local 不共享最快 → 单变量用 atomic → 多变量或一段逻辑用 mutex → 高频写的 atomic 记得 alignas(64) 防伪共享。
