## 模块一：业界背景

### Q1 推荐系统怎么处理 / 处理什么 / 处理后是什么 + 在线学习

推荐系统的标准 pipeline 是三段接力：

```
用户行为日志（曝光/点击/停留/转化）
   → ① 离线评估（T+1 批处理）          ← 我们飞轮的同构对象
   → ② 在线小流量 AB                   ← 我们 AB 框架的同构对象
   → ③ 全量上线
```

**① 处理什么**：每天把前一天的日志汇总成数据集——一部分做训练样本（点击=正样本，曝光未点=负样本），一部分做评估集（保留真实反馈做 held-out）。

**怎么处理**：新模型/新策略在**历史数据上重放**——把昨天的请求重新喂给候选模型打分，对比它和线上在役模型的排序结果，算离线指标（AUC/GAUC/NDCG@K/Recall@K）。

**处理后是什么**：一份对比报告（candidate vs 线上模型的离线指标），达标才允许进入 ② 在线 AB。**关键认知：离线好 ≠ 在线好**——离线数据是历史分布，线上是实时分布，存在样本选择偏差和分布漂移，所以必须有在线环节闭环验证。这跟我们“RAGAS 离线评估通过 ≠ 可以直接改配置，要 AB 验证”是同一个道理。

**在线学习（Online Learning）**：不走“攒数据→重训→部署”的批周期，而是**实时反馈流增量更新模型**——每个点击到达就更新一次参数（FTRL/流式 SGD），分钟级生效。三大问题：① **正反馈循环**——模型推什么用户就点什么，数据被自己的推荐污染，越学越窄；② 需要探索机制（epsilon-greedy、汤普森采样）主动试非最优内容收集真实偏好；③ 模型质量守护指标。**影子模式**是零风险变体：新模型对线上流量并行打分但不返回结果，只记录对比，验证够了再切。

对照我们：飞轮=①（T+1 离线）；AB 框架=②（在线小流量）；点赞点踩=隐式反馈信号。**我们的节奏选日级批处理是量级决定**——单用户系统的 session 量撑不起在线学习，这是诚实选择不是技术缺陷。

### Q2 AutoGPT 全自主循环是什么

AutoGPT 是 2023 年开源的自主 Agent：给它一个目标（“帮我调研并写报告”），它自己**循环执行：拆任务 → 调工具 → 观察结果 → 再规划 → 再执行**，中间没有任何人工审批节点，直到它认为“完成”。

**为什么说容易跑飞**：① **错误累积**——一步理解偏了，后面全在错误方向上继续，没有人类纠偏点；② **目标漂移**——LLM 每轮重新解释目标，慢慢跑题；③ **死循环烧钱**——卡在某个子目标反复尝试，token 烧爆；④ **不可逆动作无闸门**——删文件、发邮件直接执行。

**它不是“改提示词”**——AutoGPT 是自主任务循环；真正“改自己 prompt”的自我改进是另一族（REFLEXION 单轮自我批评、Voyager 的 skill 库沉淀）。我们的设计与它对比的核心一句话：**决策权和执行权分离**——Agent 可以建议（决策侧），执行有人工闸门（prompt 类）或硬边界（标量 min/max），这就是三类边界的出发点。

## 1. AutoGPT 不就是 ReAct 的实现吗？比 LangChain 还低级？

**你的判断基本正确，但要纠正一个比较维度**：LangChain 是**框架/库**（给你零件自己组装），AutoGPT 是**应用/产品**（装好就能跑的自主 agent）——AutoGPT 内部其实就用了 LangChain，两者不在同一层，“低级”无从谈起。

准确的技术定位：**AutoGPT = ReAct 循环 + 激进自治化**。ReAct 的核心是 `Thought → Action → Observation` 循环（每步推理决定下一步动作）。AutoGPT 在这之上加了三样东西：任务列表自我管理（自己拆解/增删子目标）、长期记忆（向量库存中间结果）、**去掉了 human-in-the-loop 的每步确认**。

“低级”的正确表述不是技术低级，而是：**自治程度激进、可靠性工程跟不上**——它等于把 ReAct 的循环放开跑到没有外部终止条件，错误累积、目标漂移、烧 token 死循环全是这么来的。历史意义恰恰在于：它用大规模翻车**证明了去掉 human gate 后错误会指数放大**，成了后来所有 Agent 框架加护栏的反面教材。面试时这是很好的叙事支点：“AutoGPT 验证了全自主不可行 → 所以我的设计是决策权/执行权分离的三类边界”——从业界教训反推出自己的架构。
