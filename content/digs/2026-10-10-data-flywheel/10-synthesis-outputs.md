## 本次整理的结构

**每张模块卡末尾新增「▸ 追问链」小节**，格式为递进式：`问 → 答`，带（追）/（再追）标记表示面试官的连续下钻路径。归属如下：

| 追问链 | 收录内容 |
|---|---|
| **A 飞轮管道** | 日级 vs 实时 → 推荐系统 T+1 三段接力 → 在线学习/影子模式；APScheduler 机制 → 失败恢复 → 为什么不用 LangGraph；防重入；阈值选择（P5 分位校准）；归因歧义（triage 非诊断）→ Agent 归因演进三段 |
| **B 反馈闭环** | 双写顺序（先难后易）→ 出错分级 → 要不要强一致（outbox 正解）；降级重复消费 → watermark/offset |
| **C 三类边界** | AutoGPT=无闸门 ReAct 辨析；prompt 外置 → variables_schema 四层缓解 → “信息不存在架构无能为力”；CI 回归集与飞轮 AB 的两道防线关系 |
| **D AB 框架**（最长，分三段） | *机制*：电台版类比 → set/reset（git commit 类比）→ 幽灵 bug 五步排查剧本 → 分流位置三论证（含“每次哈希重算”的澄清）；*传播体系*：contextvar 谱系 → OTel 两半 → W3C 头 → baggage 详解 → 标签传播 vs 确定性分桶；*实验治理*：白名单/灰度 → 正交数字例 → fail-back 顺序 |
| **E 缓存运行时** | 256KB 不进内存 → Redis 挂了自动恢复 → 大对象回源是常态非退化 |
| **F 失效粒度** | 整组失配拆解 → 全局检索低频的完整逻辑链 → 两级缓存升级路径 |
| **G 审计观测** | 观测成本预算（metrics vs events）→ 降级文件处置 SOP → pytest vs 脚本 + CI 门禁 |

**同步更新的部分**：§5 速答表扩到约 45 行（新增 AutoGPT/baggage/双写顺序/正交/幽灵排查等 16 条）；诚实声明第 9 条精确化（拦合并非拦提交）；§7 业界对照补“上下文传播”和“双写”两行；§8 记忆锚新增 7 行；文末新增**附 2：三轮追问→模块卡归属索引**（想回看某个具体讨论时按图索骥）。

**一个使用建议**：面试前重点过卡 D 的追问链——它是全文档最长、递进最深的一条（三段 18 问），也是你前面几轮追问中理解增长最明显的部分（从“类比不清楚”到能自己复述“W3C 头=跨服务的 contextvar”）。
