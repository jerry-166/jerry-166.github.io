类型转换与数值提升（完整规则）

2.1 自动类型转换：小容量 → 大容量高频★★★

容量小的类型可以自动赋给容量大的类型，不丢精度、不报错：

自动提升链（箭头方向可自动转）结构
 byte → short → int → long → float → double
                  ↑
                char（char 可自动转 int 及更大，但不能转 byte/short）

long l = 100;       // int → long ✅
float f = 10L;      // long → float ✅（能转！原因见 2.4）
double d = 10.5f;   // float → double ✅

2.2 二元数值提升：算术运算时两边统一成什么类型？难点高频★★★

规则：不是一律提升到 int！按双方类型中"更大"的那个统一，最低保底 int。判定顺序（从高到低）：

二元数值提升判定流程规则
两个操作数（byte/short/char/int/long/float/double）做 + - * / % 时：

  有 double ?  ── 是 ──→ 双方都转 double
      │否
  有 float ?   ── 是 ──→ 双方都转 float
      │否
  有 long ?    ── 是 ──→ 双方都转 long
      │否
  （只剩 byte/short/char/int）──→ 双方都转 int   ← "必升 int"只是这一步！

例子：
  1 + 2L          → long  （一方是 long）
  1 + 2.0         → double（一方是 double，注意 1 也被转成 1.0）
  1 + 2.0f        → float
  byte + byte     → int   （都 ≤ int，保底转 int）
  char + int      → int
💡 为什么 byte+byte 结果是 int？

JVM 指令集层面没有 byte/short/char 的算术指令，只有 int/long/float/double 四则指令——CPU 按字长计算更快。所以"小类型参与运算必升 int"是物理实现决定的，不是设计洁癖。

2.3 由此产生的经典编译错误易错★★★

三个必考片段Java
// ① 小类型变量相加 → 结果是 int → 赋回小类型要强转
byte b1 = 1, b2 = 2;
byte b3 = b1 + b2;            // ❌ 编译错误：b1+b2 已是 int
byte b3 = (byte)(b1 + b2);    // ✅ 显式强转

// ② 但纯常量可以 —— 编译期"常量折叠"先算出结果，只要结果在范围内就放行
byte b4 = 1 + 2;              // ✅ 编译器直接算出 3，3 ≤ 127，合法
byte b5 = 200;                // ❌ 常量但超范围，编译错误

// ③ 复合赋值自带强转（语言规范规定 E1 op= E2 ≡ E1 = (T)(E1 op E2)）
short s = 1;
s = s + 1;      // ❌ 同①：右边是 int
s += 1;         // ✅ 等价于 s = (short)(s + 1)，编译器帮你强转（可能悄悄溢出截断）

2.4 强制转换：截断与溢出易错★★★

强转 = 砍掉高位，不是四舍五入Java
// 整型强转：直接丢弃高位字节
int i = 300;             // 二进制 1 0010 1100
byte b = (byte) i;       // 只保留低 8 位 0010 1100 = 44！

// int 溢出：按补码"环绕"，不报错、不抛异常 —— 静默出错（Python 没有这个概念！）
int fact = 1;
for (int k = 1; k <= 15; k++) fact *= k;    // 13! 就超 int 了，结果是错的负数

// 想要溢出报警：
Math.addExact(Integer.MAX_VALUE, 1);        // 抛 ArithmeticException（JDK 8+）

// 浮点强转：直接砍掉小数部分（向零截断），不是四舍五入
double d = 3.99;
int x = (int) d;         // 3
Math.round(3.5)          // 4（要四舍五入用 round）

// 二分查找的经典溢出修复
int mid = (low + high) / 2;              // ❌ low+high 可能溢出成负数
int mid = low + ((high - low) >> 1);     // ✅ 先做减法就不超范围
🧩 冷门加分点：为什么 long 能自动转 float？

long 是 8 字节、float 只有 4 字节，按"字节"想不通。按"范围"想就通了：float 指数位让它能表示约 ±3.4E38，远大于 long 的 ±9.2E18——自动转换看表示范围，不看字节数。代价是丢精度（float 只有 23 位尾数，装不下 64 位整数）。这也是"范围大 ≠ 精确"的直觉来源。

⚠ Python → Java 迁移者警告

Python 的 int 无限精度、永远不会溢出；Java 的 int/long 有硬上限且溢出静默环绕。任何乘法累积、大数求和、时间戳运算前，先估算数量级（21 亿 ≈ 2^31，超过就用 long / BigInteger）。

04

浮点精度与 BigDecimal

4.1 为什么 0.1 + 0.2 != 0.3超高频★★★

float/double 采用 IEEE 754 二进制浮点：符号位 + 指数位 + 尾数位。问题出在——十进制小数转二进制可能是无限循环的：

0.1 的二进制是无限循环小数原理
0.1 (十进制) = 0.0001100110011001100... (二进制，0011 无限循环)
                                          ↑
                     double 尾数只有 52 位 → 第 53 位起只能丢弃（存成近似值）

所以：double 里存的 0.1 ≠ 数学上的 0.1，只是"最接近 0.1 的二进制数"
     0.1 + 0.2 = 两个近似值相加 ≈ 0.30000000000000004 ≠ 0.3 的近似值

→ 本质：二进制无法精确表示分母含非 2 因子的小数（0.1=1/10，10=2×5）
→ 0.5、0.25、0.125（2 的负幂）则精确无损
事故现场与特殊值Java
System.out.println(0.1 + 0.2);          // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);   // false
System.out.println(2.0 - 1.1);          // 0.8999999999999999

// 浮点判等的正确姿势：误差容忍
Math.abs(0.1 + 0.2 - 0.3) < 1e-9;

// 特殊值（Python 完全一样）：
double nan = 0.0 / 0.0;     // NaN：和任何值都不等，包括自己！
nan == nan                  // false —— 判断 NaN 只能用 Double.isNaN(nan)
double inf = 1.0 / 0.0;     // Infinity（整型除 0 才抛 ArithmeticException）
0.0 == -0.0                 // true（还有正零负零这回事）

4.2 BigDecimal：金额计算的正确姿势高频易错★★★

三个必踩的坑Java
// 坑1：用 double 构造 → 把近似值原样带进来（白瞎了 BigDecimal）
new BigDecimal(0.1);        // 0.1000000000000000055511151231257827…
new BigDecimal("0.1");      // ✅ 字符串构造才精确
BigDecimal.valueOf(0.1);    // ✅ 等效字符串（内部先 Double.toString）

// 坑2：equals 连"小数位数 scale"一起比
new BigDecimal("2.0").equals(new BigDecimal("2.00"));    // false！scale 不同
new BigDecimal("2.0").compareTo(new BigDecimal("2.00")); // 0 ✅ 比较数值用这个

// 坑3：除不尽不给精度 → 直接异常
new BigDecimal("10").divide(new BigDecimal("3"));                    // ❌ ArithmeticException
new BigDecimal("10").divide(new BigDecimal("3"), 2, RoundingMode.HALF_UP);  // 3.33 ✅

// 金额计算标准范式：字符串构造 + 最后统一 setScale
BigDecimal total = new BigDecimal("19.99")
        .multiply(new BigDecimal("3"))          // 乘法天然精确，无需精度
        .setScale(2, RoundingMode.HALF_UP);     // 最后统一保留 2 位小数
🐍 Python 对比

同构问题同构解：Python 也是 0.1 + 0.2 != 0.3，解法也是 decimal.Decimal("0.1")（同样必须字符串构造）。差异：Python Decimal 默认 28 位有效数字、默认银行家舍入（ROUND_HALF_EVEN）；Java 必须显式给 RoundingMode。数据库金额字段用 DECIMAL 类型对应。

String 深度剖析

5.1 不可变性：实现与理由超高频★★★

源码级实现Java
public final class String {          // final 类：不许继承，防止子类破坏不可变
    private final byte[] value;      // private + final：外部拿不到数组引用，内部不可重指向
    private final byte coder;        // JDK9+：标记编码（Latin-1 省一半内存 / UTF-16）
    private int hash;                // hashCode 的惰性缓存（算一次存起来）
}
// "不可变"的本质：没有任何方法能修改 value 数组的内容；
// substring/replace/concat 全部返回新对象，原串毫发无损

为什么设计成不可变？（背 4 点，每点都能展开）

  1. 字符串常量池的前提：只有不可变，多个引用才能放心共享池中同一对象（否则我改了你用的字符串，全世界遭殃）——这就是模块 1 说的"常量池在堆中省内存"的根基
  2. 天然线程安全：不可变对象无状态变更，随意跨线程共享无需加锁
  3. hashCode 可缓存：String 是 HashMap key 的头号主力，hash 算一次就缓存，put/get 提速
  4. 安全性：类名、文件路径、SQL、网络参数都是字符串，不可变防止被中途篡改

5.2 字符串常量池：接着模块 1 讲超高频难点★★★

模块 1 说过：字符串常量池 JDK 7 起在堆中，作用是让相同字面量只存一份。两种创建方式的内存差异：

字面量 vs new 的内存图结构
String s1 = "abc";               String s3 = new String("abc");

   栈              堆                  栈              堆
 ┌──────┐   ┌──────────────┐      ┌──────┐   ┌──────────┐ ┌──────────────┐
 │ s1 ──┼──→│ 常量池 "abc"  │      │ s3 ──┼──→│ 新对象    │ │ 常量池 "abc"  │
 └──────┘   │ （全局一份）  │      └──────┘   │ "abc"内容 │ │              │
            └──────────────┘                 └──────────┘ └──────────────┘
  s1 == "abc"  → true                        s3 == "abc"  → false（两个不同对象）

高频问：new String("abc") 创建几个对象？
答：最多 2 个 —— 堆中 new 的 + 常量池里的 "abc"（池中已存在则只 new 1 个）
注意：s3 的内容数组和池中对象也各自独立（new 时还拷贝了一份数组）

5.3 == 六连问（笔试最爱）超高频★★★

一条心法判定Java
String s1 = "hello";
String s2 = "hello";
String s3 = new String("hello");
String s4 = "hel" + "lo";         // 纯常量：编译期折叠成 "hello" → 指向池
String s5 = "hel";                
String s6 = s5 + "lo";            // 有变量：运行期 StringBuilder 拼接 → 堆中新对象
final String s7 = "hel";          // final + 常量初始化 = 编译期常量（宏替换）
String s8 = s7 + "lo";            // s7 被当常量折叠 → 指向池中 "hello"

s1 == s2    // true   同一个池对象
s1 == s3    // false  堆里 new 的
s1 == s4    // true   常量折叠回池
s1 == s6    // false  运行期生成的堆对象
s1 == s8    // true   final 常量参与折叠
s3.intern() == s1    // true  intern()：把 s3 的串登记进池，返回池中对象

// 【心法】看引用"编译期能不能确定"：
// 纯字面量（含 final 常量）→ 池对象；任何普通变量参与 → 堆对象
// 一律用 equals 比内容，以上只是原理剖析
intern() 是什么？JDK 6 和 7 的行为差异？

intern() = "去常量池登记，返回池中的那个对象"：池里已有等值串就返回已有的；没有就登记后返回。

JDK 6：池在永久代，空间紧张，intern 会把字符串复制一份进池，返回新地址 → new String("a").intern() == "a" 可能不等。JDK 7+：池在堆，intern 发现没有时只记录堆对象的引用，不复制 → intern 返回的就是那个堆对象本身。工程上不建议手动 intern（容易混淆），面试懂原理即可。

6.1 结论：Java 只有值传递超高频难点★★★

一句话回答

传参 = 把变量槽里的内容复制一份给形参。基本类型槽里是值 → 拷值；引用类型槽里是地址 → 拷地址。所以：方法内改对象内容外面看得见（同一对象），方法内给参数重新赋值外面看不见（改的是副本的指向）。

内存图：调用 change(p) 时发生了什么结构
static void change(Person p) {          Person p = new Person("Tom");  change(p);
    p.setName("Jerry");   // ①改对象内容
    p = new Person("X");  // ②参数重新赋值
}

   调用前                     调用中（实参 p 复制地址给形参 p'）
 ┌─────────┐  ┌──────────┐   ┌─────────┐  ┌──────────┐  ┌──────────┐
 │main栈: p│→ │ 堆:Tom对象│   │main栈: p│→ │ 堆:Tom对象│←│change栈:p'│
 └─────────┘  └──────────┘   └─────────┘  └──────────┘  └──────────┘
                                            ↑ 两个槽指向同一个对象

 ① p'.setName("Jerry")：通过地址改堆对象 → main 里的 p 也看到 Jerry ✅影响外部
 ② p' = new Person("X")：只是让 change 栈帧里那个槽改指新对象
                            → main 的 p 槽纹丝不动，还是指向 Tom ❌不影响外部
四段验证代码Java
// ① 基本类型：拷值，swap 永远失败
static void swap(int a, int b) { int t = a; a = b; b = t; }
swap(x, y);                          // x、y 不变 —— 换的是副本

// ② 引用类型改内容：外部可见
static void changeName(Person p) { p.setName("新名字"); }   // ✅ 生效

// ③ 引用类型重新赋值：外部不可见
static void reassign(Person p) { p = new Person(); }       // ❌ 无效

// ④ String 的"怪象"：其实一点不怪
static void change(String s) { s = "world"; }
String str = "hello";  change(str);  // str 仍是 "hello"
// s = "world" 属于情形③（参数重新赋值）；
// 而且 String 是不可变的，压根没有情形②可玩 —— 所以 String 参数"永远改不动"
🐍 Python 完全同构

Python 官方叫 "call by object reference / 传共享"：传"对象引用的副本"。函数内 lst.append(x)（改内容）外部可见 ↔ Java 情形②；lst = [...]（重绑定）外部不可见 ↔ Java 情形③。你写 Python 时已有的直觉可以直接迁移。真·引用传递是 C++ 的 int& 和 C# 的 ref，Java/Python/Go 都没有。

7.2 foreach 的原理与 fail-fast高频难点★★★

增强 for 循环 = 语法糖Java
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
for (String s : list) {                 // 编译器改写为：
    if (s.equals("b")) list.remove(s);  // ❌ ConcurrentModificationException！
}
// 等价展开：
// Iterator<String> it = list.iterator();
// while (it.hasNext()) { String s = it.next(); ... }

// 为什么炸：ArrayList 迭代器每次 next() 都核对 modCount（集合结构修改次数）
// 是否还等于 expectedModCount（迭代器创建时的快照）
// list.remove(s) 走集合自身方法：modCount+1，但迭代器不知情
// 下一次 next() 发现对不上 → 判定"结构被外部篡改" → fail-fast 抛异常
//（这是"提前暴露并发修改 bug"的保护机制，模块 4 集合框架展开）

// ✅ 正确删除姿势
list.removeIf("b"::equals);             // JDK8+ 内部用迭代器自己的 remove，安全
// 或迭代器：it.remove();（它删完会同步 expectedModCount）

7.3 数组要点★★

数组是对象 + Arrays 工具的两个坑Java

高频面试题速查（自测清单）

1. 八大基本类型及大小？boolean 多大？

byte(1) short(2) int(4) long(8) float(4) double(8) char(2) boolean(规范未定义，实现上单独用按 int、数组按 byte)。默认值仅成员变量有：0/0.0/false/'\u0000'/null。

2. byte b = 1+2 可以，b1+b2 赋回 byte 却不行？

1+2 是编译期常量折叠，结果 3 在 byte 范围内直接放行；b1+b2 是变量运算，二元数值提升为 int，int→byte 必须强转。复合赋值 s+=1 合法是因为规范规定其自带 (T) 强转。

3. 两个不同类型做算术运算，结果类型怎么定？

二元数值提升：有 double 转 double，其次 float，其次 long，都 ≤ int 则统一 int。不是一律 int！byte+byte 才是 int，int+long 是 long，int+double 是 double。

4. i = i++ 后 i 的值？为什么？

还是 1。执行序：旧值 1 压栈（作为表达式值）→ i 自增为 2 → 栈顶旧值 1 赋回 i 覆盖。i++ 表达式的值是自增前的旧值。

5. 0.1+0.2 != 0.3 的原因和解法？

IEEE 754 二进制浮点无法精确表示 0.1（无限循环二进制），存的是近似值。判等用误差容忍；精确计算用 BigDecimal（字符串构造/valueOf），判等 compareTo，除法必须给 scale + RoundingMode，否则除不尽抛 ArithmeticException。Python 的 decimal.Decimal 同理。

6. String 为什么不可变？如何实现？

final 类 + private final byte[]（JDK9 紧凑字符串）+ 无修改方法。收益：常量池共享、线程安全、hashCode 缓存、安全性。修改类 API 全部返回新对象。

7. new String("abc") 创建几个对象？两种创建方式 == 结果？

最多 2 个：堆中 new 的 + 常量池的（已存在则 1 个）。字面量指向池中对象，new 强制在堆创建新对象，所以 s1=="abc" 为 true 而 new String("abc")=="abc" 为 false。intern 返回池中对象（JDK7+ 池在堆，登记引用不复制）。

8. 循环里 += 拼接字符串有什么问题？

每轮 new StringBuilder + 全量拷贝，O(n²)。循环外单个 StringBuilder 复用（可预估容量），均摊 O(n)。Python 的对应物是 str.join。

9. Java 是值传递还是引用传递？

只有值传递：拷贝变量槽内容。基本类型拷值 → 方法内改不影响外部；引用类型拷地址 → 方法内改对象内容外部可见、重新赋值外部不可见。String 参数"改不动"= 不可变 + 重新赋值双重原因。

10. foreach 里 remove 会怎样？怎么正确删？

ArrayList 抛 ConcurrentModificationException：迭代器 next() 核对 modCount 与 expectedModCount，集合自身 remove 使 modCount+1 触发 fail-fast。正确姿势：iterator.remove() / removeIf / 并发集合 CopyOnWriteArrayList。

11. Arrays.asList 有什么坑？

返回定长视图（内部类 Arrays$ArrayList）：set 可以、add/remove 抛 UnsupportedOperationException；基本类型数组会被整个当一个元素（List<int[]>，size=1）。要可变就 new ArrayList<>(...) 再包一层。

12. final 修饰引用变量，对象还能改吗？

能。final 锁的是"引用的指向"（不可再 = 别的对象），不锁对象内部状态（字段照样 set）。类比 Python 的 tuple 装可变对象。
