## 第一部分：Transformer 是什么（笔记转载）

### 1. 从翻译问题说起

「货拉拉拉不拉拉布拉多」，短短 10 个字里有 6 个「拉」字，含拉量达到惊人的 60%。人一看就能理解它的意思，所以很自然就能翻译成英文：`Can Huolala carry a Labrador`。注意，关键是**理解**，所以才能翻译。

![货拉拉翻译问题](/images/transformer/huolala.jpg)

但计算机却表示很难理解。每个「拉」字在不同位置代表不同意思，尤其是中间这个「拉不拉」。在中文里，「拉」可以表示拉货，也可以表示拉扯；翻译成英文既可以是 carry，也可以是 drag 或 pull——必须结合前面的「货拉拉」和后面的「拉布拉多」，才能准确理解「拉不拉」。

那么问题就来了：**计算机该如何理解一句话里每个词的含义？**

![计算机如何理解](/images/transformer/computer.jpg)

### 2. Token 与向量

计算机只认识 01 这样的数字，所以在翻译之前，需要把文本变成数字。

最简单的方法是将文本挨个字转成对应的数字编号，比如 Unicode 编码。但编号只是纯数字，不能承载任何语义信息，两个编号之间也不会有语义关联。

![纯编号的局限](/images/transformer/unicode.jpg)

所以我们需要一种**既能数字化、又能承载语义**的方案：

1. 先将这句话切分成多个词块，每个词块叫一个 **token**——比如切成「货拉拉」「拉不拉」「拉布拉多」三个 token；
2. 想象一个二维坐标系，x 轴表示"是否和交通相关"，y 轴表示"是否和动物相关"：「货拉拉」落在 x 轴正方向，「拉布拉多」落在 y 轴正方向。"物流平台""网约车"会更靠近「货拉拉」，"金毛""牧羊犬"会更靠近「拉布拉多」。

![token 切分](/images/transformer/token-split.jpg)

但只有两个维度不够。随着维度增多（如加入"是否运货"维度，「货拉拉」「物流平台」偏向运货物，「网约车」偏向运人，就被区分开了），世界上所有已知词汇的 token 都能在这个多维坐标系里找到属于自己的位置。通过海量语料训练，可以做到**语义相近的词在空间中靠得很近，语义无关的词离得很远**。

词和词之间的关系还能通过数学方式计算出来。比如"国王"的坐标减去"男人"加上"女人"，得到的结果会非常接近"王后"的坐标。

至于「拉不拉」这种多义词，它在坐标系里只是一个模糊的平均位置，**只有结合前后词之后，它的位置才会被"拉"向正确的语义区域**。

![向量与 embedding](/images/transformer/vector.jpg)

每个坐标维度都可以表示为数字，所以每个 token 都可以用一组数字来表示，这种表示方式就是 **vector（向量）**，实践中也经常被叫做 **embedding**。

但语言不仅有词义，还有顺序。「货拉拉」和「拉布拉多」顺序颠倒时，意思完全不同。所以模型还会为每个 token 加入**位置信息**，让向量同时包含"它是什么"和"它在什么位置"。

### 3. Q、K、V 是什么

知道了每个 token 对应的向量，我们就可以考虑翻译的事情。但问题又来了：在翻译「拉不拉」这种多义词时，怎么结合上下文判断这个「拉」究竟是 carry 还是 drag？

我们知道，每个词块除了表面上的字面意思，还有背后含义。比如拉布拉多，除了字面意思，背后的含义有宠物、狗等。

所以我们可以把一句话抽象成一个**"词块数据库"**：数据库的查询键 key 就是词块本身，value 就是词块背后的含义。计算机在理解「拉不拉」时，应该重点关注哪些词，就可以抽象为：拿着「拉不拉」这个词去词块数据库里挨个遍历一遍，看哪个词对「拉不拉」参考价值更大。

![词块数据库](/images/transformer/kv-db.jpg)

但直接拿 token 的向量去做这三件事不够灵活——一个向量要同时扮演三个角色。所以我们通过三个权重矩阵 W_q、W_k、W_v 的变换，让每个 token 的向量分别变成三个专门的向量，各司其职：

![QKV 变换](/images/transformer/qkv-transform.jpg)

- **Q（Query）**：承担查询角色，代表"这个 token **想关注**什么"——就像数据库的查询 SQL；
- **K（Key）**：承担键角色，代表"这个 token **能提供**什么信息"——就像数据库的查询键；
- **V（Value）**：承担值角色，代表"这个 token 背后的**真正含义**"——就像查询键对应的值。

![QKV 三角色](/images/transformer/qkv-roles.jpg)

### 4. 注意力是什么

有了每个 token 的 QKV 之后，就可以用它们进行计算：

1. 每个 token 的 Q 会遍历句子中**所有** token 的 K，用**点积**计算相关程度；

![点积计算](/images/transformer/dot-product.jpg)

点积说白了就是相乘。从数学上看，是在计算两个向量在坐标系里指向是否一致，越同向数值越大；从效果上看，就是两者相关程度越高，这个 token 越值得被重点参考。

比如针对「拉不拉」这个 token 遍历结束后，计算机就会发现它和「货拉拉」之间相关性很高，那么「拉不拉」就会更关注「货拉拉」，后续"拉货"这一含义就会被显著放大。

2. **Scale**：如果向量维度较大，点积结果可能整体偏大，导致某个 token 的关注程度被放大得过于极端。为了让不同 token 之间的关注差异更容易被区分，模型会在点积之后除以维度的开方 √d_k；

![scale](/images/transformer/scale.jpg)

3. **Softmax**：模型对这些关注程度做一次 softmax，把它们转换成一组权重，让「拉不拉」对所有 token 的关注程度之和为 1，可以理解为"注意力分配比例"；

![softmax](/images/transformer/softmax.jpg)

4. **加权 V**：再用这组权重去加权所有 token 的 V 向量，相当于「拉不拉」这个 token 以特定权重从其他 token 那里提取并融合具体语义。

![加权 V](/images/transformer/weighted-v.jpg)

最终得到的结果，就是「拉不拉」融合了上下文信息之后的表示（记作 h2）；「货拉拉」「拉布拉多」也会以同样方式分别得到 h1、h3。

这一整套计算过程就是**注意力机制**：

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V
```

它让每个 token 根据当前语境，自动决定应该重点参考其他哪些 token。四步总结：

- **Q · K 点积**：计算 token 之间关注谁、关注程度；
- **Scale（÷√d_k）**：防止点积数值过大，避免 softmax 饱和、梯度消失；
- **Softmax**：把关注程度转换成注意力权重（概率分布）；
- **× V**：用权重从被关注的 token 中提取并融合具体的语义内容。

### 5. 多头注意力

但只算一次注意力是不够的。词与词之间的关系是多样的——有的是语义上的关联，有的是语法结构上的依赖，单一角度很难捕捉全面。

所以模型会**并行地做多次注意力计算**，每一次关注不同的侧重点，并行计算的结果最终被拼接在一起，这就是**多头注意力（Multi-Head Attention）**。

![多头注意力](/images/transformer/multi-head.jpg)

### 6. Add & Norm 是什么

通过多头注意力，原句里的各种语义信息就通过向量表示了出来。接着：

- **Add（残差连接）**：模型首先把注意力的结果和原始输入相加，确保 token 自身的信息不会被覆盖掉；
- **Norm（归一化）**：为了让数值保持在稳定范围内，模型对结果做一次统一调整。

这样做既保留原有信息，又避免数值在多层计算后失控。

![Add & Norm](/images/transformer/add-norm.jpg)

### 7. 前馈网络（FFN）

经过残差连接和归一化处理后，从原始输入到当前输出的映射关系仍然是**线性**的——不同 token 向量的变换路径都是笔直的直线，没法捕捉复杂的语义关联。

为了让模型具备更强的表达能力、拟合自然语言里非线性的语义关系，模型让向量通过**前馈网络（FFN）**。它的核心作用是通过 ReLU 等激活函数，把"线性的映射路径"掰弯，变成非线性的曲线。

![前馈网络](/images/transformer/ffn.jpg)

随后同样会再接一次 Add 和 Norm。

![FFN 后的 Add & Norm](/images/transformer/ffn-addnorm.jpg)

### 8. 编码器（Encoder）

多头注意力 → Add & Norm → 前馈网络 → 再一次 Add & Norm，共同构成一个**编码层**。

一个编码层能让模型对整句话形成一次上下文理解；多个编码层堆叠起来，模型对语义的理解就会逐层加深。多个编码层组成一个**编码器**。

![编码器](/images/transformer/encoder.jpg)

编码器的最终输出是一组向量——它们是原句的各个词块融合了上下文语义信息之后的数字表现形式，是计算机对输入文本的**整体语义理解**。

### 9. 翻译原理：解码器（Decoder）

接下来就是基于编码器输出的整体语义理解，开始翻译成英文。

生成英文时，我们会放入一个固定的起始符号 `<BOS>`（表示"英文从这里开始翻译"），模型结合编码器输出的中文理解，预测最合理的第一个英文词 `Can`；接着把 `<BOS>` 和 `Can` 一起作为输入，预测下一个词 `Huolala`，依此类推——每一步都是在已有结果的基础上预测下一个最合理的英文词，就像成语接龙。

![逐步生成](/images/transformer/decode-step.jpg)

这个过程需要解决两个问题：

**问题一：新生成的词怎么和已经写下的英文内容衔接，保证语法和表达连贯？**

用注意力机制解决。Q 是当前要翻译单词的位置，K/V 来自**已生成的英文**构成的词块数据库——预测第 n 个词时只依赖前 n-1 个词的结果，保证生成过程从左到右，就像掩盖了后面部分做词语预测，所以叫**带掩码的多头自注意力（Masked Self-Attention）**。

![带掩码的自注意力](/images/transformer/masked-attention.jpg)

**问题二：在原句已经理解好的整体语义中，此刻翻译最该参考原句哪部分信息？**

同样用注意力解决。Q 还是当前要翻译单词的位置，而 K/V 来自**中文**构成的词块数据库，这部分叫**多头交叉注意力（Cross-Attention）**。

![交叉注意力](/images/transformer/cross-attention.jpg)

比如在已经生成 `Can Huolala` 之后，再来翻译「拉不拉」时，由于编码器输出的中文理解中它和运货相关的信息关联更强，因此更可能翻译成 carry，而不是 pull 或 drag。

两次注意力计算之后，输出结果都会经过残差连接、归一化以及前馈网络。这些组件共同构成一个**解码层**，多个解码层堆叠在一起形成完整的**解码器**。

## 第二部分：Transformer 架构问题溯源（进阶）

> 第一部分讲了它怎么工作，这一部分反过来问：**这套架构本身埋下了哪些问题的种子？** 以幻觉问题为主线，从组件层面拆解缺陷的根源。

### 1. 幻觉问题：不是一个 bug，是多个组件的合谋

幻觉不是某一个地方出错，而是**至少 5 个架构层面的因素叠加**的结果。

#### ① 自注意力学的是"共现"，不是"因果"

Q·K 点积算的是 token 间的统计邻近性——哪些词经常一起出现。这让模型能流畅地把"看起来相关"的内容拼在一起，但它并不真正理解事实关系。

比如"爱因斯坦"和"提出相对论"在语料中高频共现，模型就会把它们绑定；但当问到冷门事实时，模型会用**统计上最可能的搭配**去填补，而不是去查证。这就是实体混淆、事实错配的根源。

#### ② Softmax 制造了"人工确定性"

注意力分数经过 softmax 后，被压缩成一个和为 1 的概率分布。这个过程**丢弃了模型本身的不确定性信息**——原本模糊的、多解的注意力，被强行变成了一个"看起来很确定"的权重。

这种确定性会跨层传播和放大，最终模型对自己编造的内容也表现得高度自信。

#### ③ 前馈网络是"压缩的知识库"，稀有事实天然弱

Transformer 的事实性知识主要存储在 FFN 层的参数中。但参数是对海量语料的**有损压缩**：高频事实编码得强，长尾事实（具体日期、冷门人名、精确数字）编码得弱，回忆时就容易失真或编造。

一个只在训练语料中出现过一次的事实，几乎不可能形成足够强的参数权重。

#### ④ 自回归生成：错了就一路错下去

每一步只基于前文预测下一个 token，一旦某个 token 错了，后续所有预测都建立在错误前文之上——**错误级联**。而且模型从左到右单向生成，**无法回溯修改**已经输出的内容。

此外还存在**暴露偏差**（Exposure Bias）：训练时用真实前文做输入，推理时用自己生成的前文，两者分布不匹配。

#### ⑤ 训练目标只优化"像不像"，不优化"对不对"

最大似然估计（MLE）的目标是让输出在统计上尽可能像训练语料，**没有任何事实正确性的约束**。再加上 RLHF 阶段，人类标注者普遍偏好"自信、流畅"的回答——模型学会了**虚张声势**：即使不知道，也要编一个听起来很合理的答案。

### 2. 其他问题的架构根源

| 问题 | 根源组件 | 机制 |
|------|---------|------|
| **上下文越长效果越差** | 自注意力 Softmax | 序列变长时，softmax 分母求和巨大，每个 token 分到的注意力权重被稀释，关键信息淹没在噪声中 |
| **Lost in the Middle** | 自注意力 + 位置编码 | 模型对开头和结尾的注意力天然高于中间位置，长上下文中间的事实容易被忽略 |
| **超长文本推理能力弱** | 自注意力 | 注意力稀释 + 长程依赖建模困难，跨段落的逻辑链条无法有效捕捉 |
| **训练长度外推失败** | 位置编码 | 正弦/学习式位置编码在训练长度之外无法有效泛化，超出窗口后位置关系混乱 |
| **O(n²) 计算/内存瓶颈** | 自注意力 | QK^T 是 n×n 矩阵，10 万 token 就是 100 亿个注意力权重，直接撑爆显存 |
| **知识过时** | Feed-Forward 参数 | 知识固化在参数里，训练截止后的新知识无法自动更新，只能靠重新训练或外部注入 |
| **没有"我不知道"** | 输出层 + 训练目标 | 模型被训练为总是输出高概率文本，没有天然的"拒答"或"表达不确定"的机制 |
| **偏见与刻板印象放大** | 全架构 | 训练语料中的偏见被参数化，注意力会放大统计上的关联模式，输出时进一步强化 |
| **推理/数学能力弱** | 全架构（无显式推理模块） | Transformer 本质是模式匹配器，没有符号推理引擎，多步逻辑推理靠"猜下一步"而非真正计算 |
| **注意力沉洞** | 自注意力 | 大量注意力权重被无意义 token（如开头标点）占用，有效信息分配不足 |
| **表示坍缩** | 深层网络 + LayerNorm | 深层表示趋同，不同 token 的表征差异缩小，信息容量下降 |

### 3. 架构组件 → 问题映射

**输入层（Token Embedding + Positional Encoding）**
- 位置编码外推失败：超出训练长度后位置关系混乱
- 语义与位置共享向量空间：token embedding 和 position embedding 直接相加，模型被迫在同一空间区分"是什么"和"在哪里"
- Tokenization 信息损失：分词导致拼写、细粒度语义信息丢失

**多头自注意力（Q·K → Scale → Softmax → 加权 V）**
- 共现 ≠ 因果：学统计邻近性而非真实语义关系 → 实体混淆、事实错配
- Softmax 人工确定性：丢弃不确定性信息 → 过度自信
- 注意力稀释：长文本中关键信息权重被淹没
- Lost in the Middle：中间位置关注度低于首尾
- O(n²) 复杂度：计算和内存随序列长度平方增长
- 注意力沉洞：权重被无意义 token 占用

**前馈网络 FFN（两层 MLP）**
- 参数化知识压缩：长尾事实编码弱 → 回忆失真/编造
- 知识冷热不均：高频事实强，低频事实弱
- 知识固化：训练截止后不自动更新 → 过时信息

**残差 + LayerNorm**
- 表示坍缩：深层表示趋同，信息容量下降
- 梯度传播中的信息衰减

**输出层（LM Head → Softmax → Sampling）**
- 无"我不知道"机制：总是输出高概率文本
- 采样随机性：温度/top_p 从分布尾部取 token → 编造风险
- 似然陷阱：高似然序列不一定高质量

**自回归解码**
- 错误级联：一个错 token 带偏后续全部预测
- 无法回溯：从左到右单向生成，不能修改已输出内容
- 暴露偏差：训练用真实前文，推理用自生成前文，分布不匹配

**训练目标（MLE 下一词预测 + RLHF）**
- 优化似然而非真实：只让输出"像语料"，无事实约束
- RLHF 奖励自信：模型学会虚张声势
- 缺乏显式事实核查模块：生成过程无事实一致性校验

### 4. 核心结论

Transformer 的每一个设计选择都是 trade-off：

- 自注意力换来了全局上下文感知，但 **O(n²) 复杂度**和 **softmax 确定性**是代价
- 参数化知识换来了泛化能力，但**压缩失真**和**知识过时**是代价
- 自回归换来了生成的灵活性，但**错误级联**和**无法回溯**是代价

> **幻觉不是某个零件坏了，而是这套架构在"流畅生成"和"事实准确"之间天然偏向了前者。**

这也是为什么 RAG 是目前最有效的缓解手段之一——它把事实来源从"参数里的压缩记忆"换成了"外部可查证的检索结果"，从架构外部补了这个短板。
